# CAD Import Dashboard Interaction and Mapping Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the CAD import workflow so fully enclosed selections can be mapped as one component, recurring entity/group mappings are reused, CAD lines remain visible, and tiny imported widgets remain draggable in edit mode.

**Architecture:** Keep CAD preview geometry and mapping matching in pure TypeScript helpers with direct Node assert specs. `CadImportDialogComponent` owns the import-session state and delegates signatures/persistence to a versioned browser-local mapping-scheme module. CAD widget generation marks imported widgets and enables native SCADA fitting; the existing `DashboardWidget`/Gridster boundary consumes a small pure resize-policy helper so editing behavior is deterministic and testable.

**Tech Stack:** Angular 20, TypeScript 5.9, `@svgdotjs/svg.js`, `angular-gridster2`, RxJS, `LocalStorageService`, Node assert specs, Python `unittest` for CAD SVG conversion.
